# v1.7.1 — Lifecycle rename + label dropdown fix

Patch release with two post-1.7.0 polish items.

## Changes

### Renamed "Active" → "Open"
The lifecycle pill's first state is now labeled **Open** (was "Active") to be more
clearly distinct from "Inactive" status terminology used elsewhere in the app.
- Enum: `SessionLifecycleState.Active` → `SessionLifecycleState.Open`
- Theme resource: `LifecycleActiveBrush` → `LifecycleOpenBrush`
- Pill text, tooltip, and accessibility hints updated across all 5 themes.

Persisted lifecycle data (`lifecycle.json`) is unaffected — only `Closed` ids are stored,
so existing closed-session state carries over without migration.

### Fixed: label dropdown selections weren't persisting
Clicking a different label in a session's dropdown was a no-op — the chip didn't
update and `labels.json` wasn't written. Root cause: opening the `ContextMenu`
programmatically via `IsOpen = true` doesn't propagate DataContext from the
PlacementTarget to the menu items the way a normal right-click does, so the
click handler couldn't resolve which session card the click came from.

Fix: explicitly propagate `ContextMenu.DataContext` from the chip's DataContext
when opening, and prefer `MenuItem.DataContext` (with the ancestor-walk as a fallback)
in the click handler. Label changes now persist on the first click.

Also removed two stray hidden duplicate `<Border>` elements left over from the
lifecycle-pill work.

## Upgrade

Download `CopilotSessionManager-v1.7.1-win-x64.zip`, extract, and run
`CopilotSessionManager.exe`. No data migration required.
